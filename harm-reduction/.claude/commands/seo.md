Audit and improve SEO for ravewellness.org — an Astro static site deployed on Vercel.

**Usage:**
- `/seo audit` — run a full SEO audit against the checklist and output a prioritized punch list
- `/seo fix <item>` — implement a specific fix from the checklist
- `/seo fix all` — implement all quick-win fixes that don't require new assets

---

## Site context

- **Stack:** Astro (static output) + Vercel
- **Base layout:** `src/layouts/BaseLayout.astro` — all meta tags, OG, Twitter, schema injection, RSS link, sitemap link live here
- **Blog posts:** `src/pages/blog/[...slug].astro` — generates BlogPosting + BreadcrumbList schema per post
- **Content collection:** `src/content.config.ts` — Zod schema for blog frontmatter
- **Sitemap:** auto-generated by `@astrojs/sitemap` at build time, referenced in `<head>` and `robots.txt`
- **RSS:** `src/pages/rss.xml.ts` — @astrojs/rss feed of all blog posts
- **llms.txt:** `public/llms.txt` — static AI discovery file
- **Redirects:** `vercel.json`

**Key paths:**
- Drug guides: `/mdma.html`, `/ketamine.html`, `/lsd.html`, `/psilocybin.html`, `/cocaine.html`, `/ghb.html`, `/poppers.html`, `/2cb.html`, `/nitrous.html`
- Tools: `/interactions.html`, `/test-kits.html`, `/hearing.html`
- Blog: `/blog.html`, `/blog/<slug>.html`
- Other: `/faq.html`, `/rss.xml`, `/sitemap-index.xml`, `/llms.txt`

## SEO checklist

### Critical (directly affect rankings / indexing)

- [ ] **Canonical URL on every page** — prevents duplicate content penalties. All pages have explicit canonical in BaseLayout. Check that blog posts derive it as `https://www.ravewellness.org/blog/${post.id}.html`
- [ ] **`robots` meta with snippet directives** — `content="index, follow, max-snippet:-1, max-image-preview:large, max-video-preview:-1"` tells Google it may show full snippets and large preview images in search results. **Already implemented.**
- [ ] **`<link rel="sitemap">` in `<head>`** — references `sitemap-index.xml` for crawler discovery. **Already implemented.**
- [ ] **`<link rel="alternate" type="application/rss+xml">` in `<head>`** — RSS autodiscovery for readers and AI agents. **Already implemented.**
- [ ] **Sitemap listed in `robots.txt`** — `Sitemap: https://www.ravewellness.org/sitemap-index.xml`. **Already implemented.**
- [ ] **One H1 per page** — never zero, never two. Validate by grepping built HTML or reading page source.
- [ ] **Unique title + description on every page** — no two pages share a title or description. Run `grep -r "title:" src/content/blog/ | sort` to spot duplicates.
- [ ] **Title length: 50–65 characters** — longer gets truncated in SERPs.
- [ ] **Meta description length: 120–160 characters** — shorter gets padded; longer gets cut.

### Structured data / schema

- [ ] **BlogPosting schema on all blog posts** — use `BlogPosting` (not `Article`) with `headline`, `description`, `datePublished`, `dateModified`, `image`, `author`, `publisher`, `mainEntityOfPage`. **Already implemented in `[...slug].astro`.**
- [ ] **BreadcrumbList on all blog posts** — links Home → Blog → Post. **Already implemented.**
- [ ] **FAQPage schema on `faq.astro`** — each Q&A pair as a `Question`/`acceptedAnswer`. **Already implemented.**
- [ ] **WebSite schema on homepage** — with `name`, `url`, `description`. Consider adding `SearchAction` if site search is added.
- [ ] **`dateModified` distinct from `datePublished`** — add a `lastmod` field to blog frontmatter Zod schema when posts are updated. Currently `dateModified` mirrors `datePublished`.
- [ ] **Validate schema with Google Rich Results Test** — run `https://search.google.com/test/rich-results` on key pages after deploy.

### Open Graph / social

- [ ] **OG image is a PNG/JPEG (not SVG)** — currently using `android-chrome-512x512.png`. **Ideal: create a dedicated 1200×630px `og-image.png`** in `public/`. Update BaseLayout once created.
- [ ] **OG image width/height tags** — `og:image:width` and `og:image:height`. **Already implemented.**
- [ ] **OG image alt tag** — `og:image:alt`. **Already implemented.**
- [ ] **OG image is absolute URL** — must start with `https://`. **Already implemented.**
- [ ] **Per-post OG images** — longer-term: generate post-specific OG images using satori + sharp at build time. Not yet implemented; fallback site image is fine for now.

### Content & structure

- [ ] **Opening paragraph answers the primary question** — enables Google featured snippets and AI Overview extraction. See blog skill style guide.
- [ ] **`## Quick answers` FAQ block near top of each blog post** — `## Quick answers` section with bold Q&A pairs. Already part of blog skill standard.
- [ ] **Descriptive anchor text on internal links** — "our [MDMA harm reduction guide](/mdma.html)" not "click here".
- [ ] **Alt text on all `<img>` tags** — build validation: `grep -r '<img' dist/ | grep -v 'alt='` to catch missing alt attributes.
- [ ] **No broken internal links** — run `npx broken-link-checker https://www.ravewellness.org` or equivalent after deploy.

### AI / modern discovery

- [ ] **`llms.txt` at `/llms.txt`** — machine-readable site summary for AI models. **Already implemented at `public/llms.txt`.** Keep updated when major new content is added.
- [ ] **RSS feed at `/rss.xml`** — full post list with titles and descriptions. **Already implemented via `@astrojs/rss`.**
- [ ] **`LLMs:` directive in `robots.txt`** — points crawlers to `llms.txt`. **Already implemented.**

### Performance (Astro handles most automatically)

- [ ] **No render-blocking scripts** — all `<script>` tags are `async` or `defer`. Verify in build output.
- [ ] **Fonts: use `display=swap`** — already in Google Fonts URL.
- [ ] **Images use explicit `width` and `height`** — prevents Cumulative Layout Shift (CLS). Any `<img>` without dimensions can hurt Core Web Vitals.

### Redirects & errors

- [ ] **301 redirects for changed URLs** — add to `vercel.json` under `"redirects"` array. Format: `{ "source": "/old-path", "destination": "/new-path", "permanent": true }`
- [ ] **404 page has `noindex`** — add a `404.astro` page if not present; include `<meta name="robots" content="noindex">` in its head.

## How to implement fixes

### Add a 1200×630 OG image
1. Create `public/og-image.png` (1200×630, brand colors, site name)
2. In `BaseLayout.astro`, change the three OG image lines:
```astro
<meta property="og:image" content="https://www.ravewellness.org/og-image.png" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
```
3. Update `<meta name="twitter:image">` to match.

### Add `dateModified` to blog frontmatter
1. In `src/content.config.ts`, add `lastmod: z.date().optional()` to the Zod schema.
2. In `src/pages/blog/[...slug].astro`, update the schema:
```js
"dateModified": (post.data.lastmod ?? post.data.date).toISOString(),
```
3. When updating a post, add `lastmod: YYYY-MM-DD` to its frontmatter.

### Add SearchAction to WebSite schema
Only relevant if site search (e.g., Pagefind) is implemented. Add to homepage schema:
```json
"potentialAction": {
  "@type": "SearchAction",
  "target": "https://www.ravewellness.org/search?q={search_term_string}",
  "query-input": "required name=search_term_string"
}
```

### Run a duplicate title/description check
```bash
grep -h "^title:" src/content/blog/*.md | sort | uniq -d
grep -h "^description:" src/content/blog/*.md | sort | uniq -d
```

### Check for missing alt text in built output
```bash
grep -r '<img' dist/ | grep -v 'alt=' | head -20
```

### Validate structured data
After deploy: https://search.google.com/test/rich-results
Check: BreadcrumbList, FAQPage, BlogPosting, WebSite

## What NOT to prioritize

- **Keyword stuffing** — modern search is vector-based. Clear topic coverage matters more than exact phrase repetition.
- **Keywords meta tag** — Google ignores it; Bing gives it minimal weight. Already removed from most pages.
- **hreflang** — not relevant unless the site adds non-English content.
- **Per-collection sitemaps** — the current single sitemap is fine at 36 pages. Only split when approaching 1000 entries.

1. Run `npm run build` — verify 0 errors
2. Check `dist/sitemap-0.xml` — confirm new pages appear
3. Check `dist/rss.xml` — confirm new posts appear
4. Submit sitemap to Google Search Console: `https://search.google.com/search-console`
5. Submit sitemap to Bing Webmaster Tools: `https://www.bing.com/webmasters`
